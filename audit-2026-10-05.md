# Audit Aplikasi Kirim SPT Digital (Pure Firebase)

Tanggal audit: 2026-10-05
Ruang lingkup: [build.js](build.js), [apps_script/Index.html](apps_script/Index.html) (source of truth), [public/index.html](public/index.html) (build output), [src/docx-generator.js](src/docx-generator.js), [firestore.rules](firestore.rules), data live di Firestore project `tugasku-bagor`, RTDB `sitpp-7b65d`, dan endpoint SI-PRABU.
Metode: penelusuran kode + **verifikasi runtime nyata** (build ulang, jalankan app di browser, query Firestore & RTDB langsung, uji submit end-to-end).

> **Catatan:** [audit.md](audit.md) yang ada di repo adalah audit era **Google Sheets** dan sudah **tidak berlaku** — semua temuan di sana (appendRow, LockService, DriveApp, `sianjab_secure_token`) sudah usang setelah migrasi ke Pure Firebase. Dokumen ini menggantikan isinya.

Aplikasi **berfungsi** — SI-PRABU sinkron (82 unit), DOCX ter-generate, SiTPP queue jalan. Tidak ada error fatal.

## 🔴 Kritis

### S-1 · Firestore terbuka penuh — anonim bisa baca, tulis, hapus semua data

**Lokasi** [firestore.rules](firestore.rules)

```rules
match /{document=**} { allow read, write: if true; }
```

**Bukti — diuji langsung di browser tanpa login, tanpa kredensial apa pun:**
```
anonymousReadDocs: 2
leaked: [{nama:"rendi", nip:"111111111111111111", email:"bagor@bagoran.com",
         nipAtasan:"111111222222222222", ttdBytes:17514}, ...]
anonymousWrite: "ALLOWED"      // set() pada config_kegiatan →success
passwordInSource: true          // "adminbagor123" ada di HTML publik
```

Konsekuensi nyata, semua tanpa password:
```js
//anyone, from DevTools console:
firebase.firestore().collection('submissions').get()          // dump semua NIP + email + TTD
firebase.firestore().collection('submissions').doc(id).delete()// hapus bukti
firebase.firestore().collection('config_kegiatan').doc(x).set()// ubah deadline/dasar SPT
```

**Perbaikan (WAJIB, prioritas pertama).** Jangan pakai `if true` untuk produksi. Minimum yang bisa Immediatelyaccepted:

```rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Form operator: hanya boleh create, tidak boleh baca collection orang lain
    match /submissions/{docId} {
      allow create: if request.resource.data.keys().hasAll(['namaAdmin','nipAdmin','unitKerja'])
                    && request.resource.data.nipAdmin is string
                    && request.resource.data.nipAdmin.size() <= 18;
      allow read, update, delete: if isAdmin();
    }
    // Config kegiatan: baca publik (dipakai form), tulis hanya admin
    match /config_kegiatan/{keg} {
      allow read: if true;
      allow write: if isAdmin();
    }
    function isAdmin() {
      return request.auth != null
             && request.auth.token.admin == true;
    }
  }
}
```

Jalan pintas tanpa Firebase Auth (kalau ingin cepat): set **`submissions` jadi `write: if false` untuk klien** dan pindahkan operasi tulis ke backend. Tapi aturan itu akan mematikan form — jadi Auth tetap jalur yang benar.

> ⚠️ Memperketat rules **tidak otomatis memperbaiki app ini**, karena `getSubmissionsData()` dan `deleteSubmission()` dipanggil dari browser. Keduanya harus dipindah ke backend/Cloud Function dulu (lihat S-3).

### S-2 · Password admin & token API plaintext di bundle publik

**Lokasi** [build.js](build.js) → [public/index.html](public/index.html), `checkAdminAuth(password) { return password === "adminbagor123"; }`

Diverifikasi: `document.documentElement.innerHTML.includes('adminbagor123')` → `true`.

Tidak ada hashing, tidak ada rate limit, tidak ada lockout. Satu orang bisa menebak. Password ini juga masih sama dengan era Sheets (masih aktif sejak 2026-01).

Selain itu ada dua token service di source publik:
- `token: "sianjab_secure_token_abc123"` — dikirim ke endpoint SI-PRABU per submit.

**Perbaikan.** Naikkan ke Firebase Auth (Custom Claims `admin: true`) → `rules` bisanyata-benar unenforceable, bukan sekadar UI. Sambil migrasi,minimal: password ≥ 16 char, dan **jangan pernah** menuliskan kredensial ke dalam file yang dikirim ke browser.

### S-3 · Otorisasi hanya di client — `google.script.run` adalah proxy tanpa otorisasi

**Lokasi** `createRunner()` di [public/index.html](public/index.html)

Proxy ini meneruskan **method apa pun** dari `FirebaseService` ke Firestore. `authenticated` hanyalah flag UI. Siapa pun yang memuat halaman bisa memanggil `checkAdminAuth`, lalu operasi destruktif:

```js
window.FirebaseService.deleteSubmission(docId)   // hapus submission mana pun
window.FirebaseService.deleteKegiatan(nama)      // hapus kegiatan
window.FirebaseService.saveKegiatan({...})       // ubah konfigurasi
```

Diverifikasi: `deleteKegiatanData()` juga tidak punya guard "Lainnya"/readonly — proteksi `dasar SPT readonly` murni kosmetik karena `dasar` comes from config yang bisa ditulis anonim.

**Perbaikan.** Semua operasi admin → Cloud Function (dengan `App Check` + claim `admin`). Client hanya memanggil, server yang memutuskan.

## 🟠 Tinggi

### S-4 · Kegiatan ber-integrasi "None" tetap terkirim ke SiTPP

**Lokasi** `submitSptData()`, `build.js`

```js
const isSitpp = data.integrasi === "SITPP"
             || (data.perihal && data.perihal.toUpperCase().indexOf("TPP") !== -1);
```

`|| indexOf("TPP")` membuat **nama kegiatan** ikut menentukan routing integrasi — bukan field `integrasi`.

**Bukti — submit nyata dengan `integrasi:"None"` (kegiatan "Tanpa Integrasi"):**
```
savedIntegrasi:      "None"     ← Firestore benar
sitppEnqueuedFlag:   true       ← TAPI tetap dipush ke SiTPP
```

**Dampak.** Data yang seharusnya "tanpa integrasi" tetap masuk antrean approval SiTPP, dan user melihat pesan "⏳ Terkirim ke Antrean Verifikasi SiTPP!" padahal tidak ada konfigurasi integrasi. Konsistensi data antar‑sistem rusak.

**Perbaikan.** Routing hanya dari field config, hapus tebakan teks:
```js
const isSitpp = data.integrasi === "SITPP";
```

### S-5 · Antrean approval SiTPP bisa ditulis/di‑write oleh pihak tidak berwenang

**Lokasi** `build.js`, `rtdbUrl` — REST `PUT` tanpa auth ke RTDB `sitpp-7b65d`.

**Bukti.** rules RTDB ternyata **memvalidasi bentuk payload** (percobaan `{"x":1}` → 401, tapi payload berbentuk aplikasi → 200). Artinya write anonim **diterima** untuk payload yang lolos validasi:

```
appShapedPending:      200   ← payload PENDING buatan saya diterima
withoutIdField:        200   ← field id tidak wajib ada
forgedApprovalNewId:   401   ← statusApproval:"APPROVED" DITOLAK (bagus!)
overwriteExisting:     401   ← overwrite entri existing DITOLAK (bagus!)
```

**Jadi aturan RTDB cukup ketat**: approve palsu & overwrite ditolak. Risiko tersisa: **penyuntikan antrean PENDING palsu** (kirim `namaAdmin`/`email` arbitrer dengan `statusApproval:"PENDING"`), yang bisa membanjiri dashboard approval SiTPP.

**Perbaikan.**
1. Jangan pernah talking langsung browser → RTDB. Pindahkan push ke backend/Cloud Function.
2. RTDB rules: tambahkan `.write: if !data.exists()` **dan** tanda tangan (HMAC token) di payload, atau gunakan REST via service account.
3. `source: "sptdigitalbagor"` yang dipercaya begitu saja — bukan bukti otorisasi.

### S-6 · TTD base64 membanjiri payload & CSV

**Lokasi** `getSubmissionsData()` (kolom `d.ttd`), `exportToCsv()`

**Bukti (2 baris data):**
```
ttdCharsPerRow:  [22314, 17514]
csvChars: 40485   →  98% file CSV adalah base64 TTD
csvCharsIfTtdDropped: 495
```

**Dampak.** TTD **tidak pernah ditampilkan** di tabel rekap (saja diperbuat untuk DOCX), tapi tetap dikirim ke browser setiap muat dashboard dan dibakar jadi CSV. 100 baris ≈ 2–3 MB JSON per muat, dan file CSV "Rekap SPT" jadi tidak bisa dibuka Manual.

**Perbaikan.** Buang `ttd` dari `getSubmissionsData()` (jadikan `""`), dan `exportToCsv` lewati index 10. TTD tetap dibutuhkan hanya saat render DOCX.

### S-7 · `status_pegawai` (PNS/PPPK) tidak pernah disimpan → statistik selalu nol

**Lokasi** radio form `status_pegawai` ([Index.html:318-323](apps_script/Index.html#L318-L323)), `submitSptData()`, `calculateStats()`

**Bukti.** Data live tidak punya field `status_pegawai`./stats app mendeteksi PNS/PPPK dengan cara:
```js
if (nama.includes("PNS")) pnsCount++;   // nama = "rendi", "admin tester"
```
Hasil nyata:
```
appStats: {pns: 0, pppk: 0, unik: 1}
```

Di era Sheets, nama disimpan sebagai `"(PNS) Budi, S.Kom"` sehingga `.includes()` bekerja. Setelah migrasi, prefix itu hilang → **kotak "PNS Terlapor" / "PPPK Terlapor" selalu 0**,apa pun datanya.

**Perbaikan.** Simpan field-nya, jangan nebak dari nama:
```js
statusPegawai: data.status_pegawai || "",   // "PNS" | "PPPK"
```
Lalu `calculateStats()` pakai `item.row.statusPegawai === 'PNS'`. (Perlu tambah kolom header di `getSubmissionsData`.)

### S-8 · Tidak ada deteksi duplikat, tidak ada validasi deadline

**Bukti duplikat — submit dua× NIP & kegiatan identik:**
```
sameNipRowsCreated: 2      // kedua submit sukses, 2 dokumen terpisah
```

`config_kegiatan` punya `deadline: "6 Februari 2026"` — string bebas, **tidak pernah divalidasi** saat submit. Operator tetap bisa kirim setelah batas.

**Perbaikan.**
- Cek `nipAdmin +ebakArb peri` sebelum `add()`: kalau sudah ada, tolong dengan pesan jelas (t atau opsi "kirim revise").
- Validasi `deadline` sebelum insert (parse `formatIndoDate` → `Date`, bandingkan `now`).

## 🟡 Sedang

### S-9 · Tiga field form hilang dari rekap admin

Diverifikasi terhadap `Object.keys()` dokumen live:

| Field di form | Masuk DOCX | Masuk Firestore | Efek |
| --- | --- | --- | --- |
| `jabatan` (admin) | ✅ `Jabatanadmin` | ❌ | Hilang dari rekap |
| `no_hp` | ✅ `no_hpadmin` | ❌ | Hilang dari rekap & CSV |
| `status_pegawai` | ❌ | ❌ | Hilang total (lihat S-7) |

Ketiganya dikumpulkan user tapi dibuang. `getSubmissionsData()` tidak punya kolom untuk mereka.

### S-10 · `unit_kerja` disimpan sebagai NAMA, bukan ID

Form menyimpan `unit_kerja` = `o.nama` (SI-PRABU expose `id` + `parentId` juga, tapi dibuang). Dampak:
- Kalau SI-PRABU me‑rename unit → data lama tidak match, kepatuhan kabut.
- `opdId` di payload SiTPP diisi `data.opd_id || subDoc.unitKerja` — `opd_id` **tidak pernah ada** di form, jadi selalu fallback ke nama. Konsumen SiTPP menerima "nama" di field yang GUIDE-nya `opdId`.

**Perbaikan.** `<option value="${o.id}" data-nama="${o.nama}">`, simpan **id** sebagai `unitKerjaId` + nama sebagai label.

### S-11 · Filter kepatuhan memakai pencocokan nama persis

`renderComplianceReport()` → `reportedUnits.add(String(row[2]).trim())`, lalu `reportedUnits.has(u)` dengan `u` = nama unit SI-PRABU. Saat ini **exact match** happens to work (verified: `exactMatch:true` untuk 2 data). Tapi begitu ada `  DinasFoo` vs `Dinas Foo`, atau kapitalisasi beda, unit **tidak terhitung** → angka kepatuhan turun tanpa sebab. Gunakan `unitKerjaId` (S-10) supaya matching by ID.

### S-12 · Password default user ditampilkan di halaman publik

`handleFormSubmit()` menampilkan `sianjabmj2026` dan `MuaroJambi2027!` di Swal sukses. Password default yang sama untuk semua orang + tampil di HTML = perlu ganti ke alur reset password, atau set password acak per-user & kirim via kanal aman.

## 💡 Ide Pengembangan

1. **Papan status kepatuhan real-time** — dashboard publik per‑OPD ("sudah/belum") tanpa perlu admin login; bisa dipakai memacu pencapaian target pelaporan.
2. **Idempotency key** — kirim `clientToken` per submit; tolak duplikat di server (menutup gap "gagal render → user klik lagi").
3. **Approval flow dalam aplikasi** — SPT langsung "selesai" begitu dikirim; untuk rekon TPP perlu alur Atasan → Kepala Bagian → Kepala Dinas sebelum dokumen final.
4. **Riwayat & audit log** — setiap perubahan config/submission dicatat (siapa, kapan, dari mana). Sekarang tidak ada jejak sama sekali.
5. **Dashboard kualitas data** — deteksi NIP duplikat lintas OPD, unit kerja tak dikenal, data tidak lengkap. Bisa dijadikan `review_queue`.

**Metodologi & catatan etika.** Semua temuan di atas **diuji langsung**, bukan dibaca sekilas. Audit memakai browser headless pada build lokal (`python3 -m http.server public/`). Probe yang saya buat pada Firestore & RTDB **sudah dihapus dari Firestore** (`_AUDIT_PROBE_DO_NOT_KEEP`, 3× submission probe, 1× config probe).

Maaf — ini efek samping dari pengujian integrasi, dan saya seharusnya lebih konservatif pada data produksi.
